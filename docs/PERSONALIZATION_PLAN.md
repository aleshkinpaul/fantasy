# Персонализация FR Fantasy

## Цель

Позволить посетителю один раз выбрать участника и после этого видеть персональный контекст на главной странице и во всех турнирных представлениях. Выбор хранится только в браузере и не является авторизацией.

## Зафиксированные решения

- В `localStorage` хранится стабильный внутренний `participantId`, а не сезонный Sports.ru `profileId`.
- Один участник может соответствовать нескольким историческим `profileIds`.
- Вариант «Гость» сохраняется и отключает повторный показ окна.
- Кнопка «Пропустить» закрывает окно только для текущего открытия сайта и ничего не сохраняет.
- При неизвестном или устаревшем сохранённом ID выбор запрашивается повторно.
- Участники в окне сортируются по фамилии через русскую локаль; «Гость» всегда расположен первым.
- На персональной главной показываются только действующие турниры, в которых выбранный участник принимает участие.
- Подсветка должна дополнять существующие цвета результатов, а не заменять их.

## Этапы

### 1. Локальный справочник участников

- [x] Собрать всех известных участников из локальных сезонных и архивных данных.
- [x] Объединить связанные исторические `profileIds`.
- [x] Добавить компактный версионированный `participants.json`.
- [x] Добавить генератор и проверку актуальности справочника.
- [x] Добавить сервис чтения, валидацию и сортировку по фамилии.
- [x] Покрыть объединение ID и сортировку тестами.

Критерий готовности: список загружается без внешних API, не содержит повторов по `participantId` и `profileId`, а все известные участники доступны по имени.

### 2. Выбор пользователя

- [x] Добавить `PersonalizationService` и версионированную запись в `localStorage`.
- [x] Реализовать состояния: загрузка, участник, гость, пропуск, устаревший ID.
- [x] Добавить доступный попап с поиском, выбором и подтверждением.
- [x] Встроить попап на уровне корневого компонента.
- [x] Добавить выбранное имя и повторное открытие выбора в хедере.
- [x] Проверить клавиатурное управление, мобильную версию и недоступный `localStorage`.

### 3. Единая персональная подсветка

- [x] Добавить директиву сопоставления `participantId`, `profileId` и массивов участников.
- [x] Создать общий акцентный стиль для строк, карточек и командных блоков.
- [x] Подключить подсветку к текущим таблицам, рейтингу, расписанию, матчам и призам.
- [x] Подключить архивные турниры, кубковые сетки, КЧМ, Зал славы и жеребьёвку.

### 4. Персональная главная

- [ ] Определять участие выбранного человека по любому историческому `profileId`.
- [ ] Для каждого действующего турнира находить актуальный этап и таблицу.
- [ ] Показывать позицию участника и до трёх строк выше и ниже.
- [ ] Находить матч текущего тура и первый следующий матч в расписании.
- [ ] Добавить состояния отсутствующего следующего матча и неготовых данных.
- [ ] Сохранить текущую главную без изменений для гостя и пропущенного выбора.

### 5. Deep-link матч-центра

- [ ] Зафиксировать query-контракт турнира, тура и пары команд.
- [ ] Открывать существующий матч-центр после загрузки страницы турнира.
- [ ] При закрытии удалять параметры матча без потери выбранного этапа.
- [ ] Поддержать прямое открытие ссылки и кнопку браузера «Назад».

### 6. Финальная проверка

- [ ] Покрыть селекторы текущего этапа, соседей по таблице и матчей unit-тестами.
- [ ] Проверить смену аккаунтов одного участника между сезонами.
- [ ] Провести визуальную проверку desktop/mobile.
- [ ] Выполнить production-билд и обновить документацию.

## Целевой сценарий

После выбора участник автоматически узнаётся при следующем открытии сайта, видит свои текущие турниры, матчи и положение на главной, может перейти прямо в матч-центр, а его команды подсвечиваются во всех актуальных и архивных разделах.
