# Добавление сезона 2026–27

Цель — добавить Ла Лигу и Лигу чемпионов 2026–27 с тем же пользовательским форматом, что и в сезоне 2025–26. Это план подготовки; конкретные URL API, участники, жеребьевка и призы должны быть предоставлены или сформированы перед реализацией.

## Что означает «тот же формат»

Для текущей архитектуры безопасное базовое предположение:

- использовать `LeagueH2HPageComponent` и маршруты `/spain/new`, `/champions-league/new`;
- выбирать сезон через `?year=2026`;
- сохранить H2H-начисление 3/1/0;
- сохранить ничью при разнице FO до `drawGap` включительно;
- сохранить структуру этапов, таблиц, кубка и вкладок 2025–26;
- создать новые данные, URL и assets, не заменяя запись 2025–26.

Фактические размеры лиг, число туров, переходы между этапами и призы нужно подтвердить отдельно. Копировать календарь 2025–26 как готовый нельзя: profile id и пары должны соответствовать новому составу участников.

## Необходимые входные данные

- список участников каждой лиги с `profile.id`, ФИО, ником, ссылкой, полом и логотипом;
- точные slugs/URL `full_info` и `sport_players_tour_stat` для каждого этапа;
- состав конференций/дивизионов;
- календарь H2H по турам или правила его генерации;
- границы этапов;
- кубковые туры, названия раундов и пары;
- список призов и формула определения каждого номинанта;
- изменения `drawGap`, лимитов замен и tie-breaker относительно 2025–26.

## Пошаговое подключение

### 1. Проверить API нового сезона

Для каждого URL проверить:

```text
full_info.data.tours
full_info.data.players
full_info.data.players[id].team.results_by_tour
full_info.data.players[id].team.rosters_by_tour
tour_stat.data.players
```

Особенно важны `team_cost`, непрерывность туров и совпадение profile id. Если ЛЧ снова разделена на два внешних турнира, потребуются обе пары `squad_link[_2]` и `tour_link[_2]`.

### 2. Создать сезонные файлы

Создать по одному документу на турнир:

```text
src/assets/data/seasons/2026-27/spain.json
src/assets/data/seasons/2026-27/champions-league.json
```

Каждый файл имеет оболочку `{ "config": {...}, "profiles": [...] }`. Массив `profiles` содержит локальные данные участников, резервов и гостей конкретного соревнования. Логотипы рекомендуется хранить в `src/assets/logos/2026/scaled/`. Пути в JSON должны быть относительны от `assets/` и учитывать регистр имени файла на Linux-hosting.

### 3. Добавить конфигурации лиг

В поле `config` соответствующего сезонного файла добавить:

```json
{
  "id": "...",
  "type": "spain",
  "typeId": "...",
  "squad_link": "https://fantasy-h2h.ru/api/h2h_tournament/full_info/...",
  "tour_link": "https://fantasy-h2h.ru/api/fnts_tournament/sport_players_tour_stat/.../",
  "yearStart": 2026,
  "yearEnd": 2027,
  "drawGap": 3,
  "rulesId": "season-2026",
  "format_img_link": "assets/images/...",
  "matches": {},
  "profiles": [],
  "stages": [],
  "prizes": [],
  "cup": {}
}
```

Создать отдельный файл для `champions-league`. Данные 2025–26 не изменять. Все рабочие ссылки обязаны передавать `?year=2026`. Для `rulesId: season-2026` сначала нужно добавить набор в `competition-rules.registry.ts`; отсутствие набора завершит загрузку понятной ошибкой.

### 4. Сформировать календарь

Для каждого тура заполнить `matches[tour]`. И вкладка матчей, и расписание участника строятся из этого поля; отдельный `stages[].leagues[].schedule` создавать не нужно.

Минимальные проверки:

- каждый участник играет ожидаемое число матчей;
- в туре нет повторного участия одного profile id;
- `home !== away`;
- все id принадлежат нужной лиге этапа;
- границы этапов покрывают нужные туры без пересечения/пропусков;
- число матчей соответствует формату лиги.

### 5. Настроить кубок

Синхронно заполнить `cup.matchesTours`, `cup.matchesToursNames` и `cup.matches`. Пары содержат profile id, а не индексы. Нужно решить правило ничьей в play-off: сейчас порог ничьей отключается, но абсолютное равенство FO все равно дает `result = 0`.

### 6. Перенести и проверить призы

Карточки находятся в `config.prizes` сезонного файла, а формулы — в `competition/domain/prize-calculator.ts`. Все специальные profile/player/team id сезона должны задаваться в новом наборе `competition/config/competition-rules.registry.ts`, а не добавляться в компонент или calculator.

Для Испании требуется заполнить `SpainPrizeRules`: гостевые профили, дополнительные исключенные победители, reference-профили призов 2/3/10, id часто используемого игрока и капитана. Если регламент или набор призов меняется, следует добавить новую стратегию отдельным изменением и не обновлять golden 2025–26.

### 7. Обновить UI

В `main-page.component.html` добавить основные ссылки:

```text
spain/new?year=2026
champions-league/new?year=2026
```

Ссылки 2025–26 перенести в архивный блок, но оставить на H2H-route с `year=2025`. Также проверить название сезона, `format_img_link`, header и CSS-темы. Общие fallback-медали уже вынесены в сезонно-независимый каталог `assets/icons/prizes`.

### 8. Провести приемку

Проверить как минимум:

- прямое открытие каждой ссылки и browser refresh;
- desktop и mobile layout;
- все вкладки этапов, конференций, туров и кубка;
- таблицы по H2H-очкам и FO;
- матч с разницей ровно `drawGap`;
- расчет первого тура и переход между этапами;
- объединение двух API для ЛЧ;
- участника без локального профиля/API-команды;
- отсутствие `undefined`, `NaN` и ошибок в console;
- production build.

## Сезонно-зависимые места в коде

| Место | Зависимость |
|---|---|
| `main-page.component.html` | URL и подписи 2025/26 |
| `assets/icons/prizes/` | общие fallback-медали, не требующие копирования в новый сезон |
| `competition-rules.registry.ts` | специальные profile/player/team id, лимиты замен по турам и выбор правил по `rulesId` |
| `prize-calculator.ts` | формулы призов и соответствие numeric prize id стратегии |
| `assets/data/seasons/2026-27/*.json` | профили, пути к иконкам/форматам и весь регламент актуального сезона |
| `consts.json`, `profiles.json`, `teams.json` | legacy-источники только архивных страниц |

Полезная команда инвентаризации:

```bash
rg -n "2025|2026|taboo|larinId|prizeInd|team_id ===|includes\(tourIndex\)" src/app src/assets/data
```

## Рекомендуемая подготовка

Подготовка уже выполнена:

1. введены `SeasonCompetitionConfig`, API-модели и runtime-валидация;
2. загрузка, объединение этапов и orchestration находятся в loader/facade;
3. H2H, таблицы, рейтинг, кубок, специальные показатели и призы вынесены из page-компонента;
4. специальные id собраны в registry сезонных правил;
5. `npm run verify:season-2025` воспроизводит три турнира из fixtures и сравнивает шесть наборов golden-данных.

Сезонная файловая структура, единый календарь `matches`, типизация актуального контура и сезонно-независимые общие UI-иконки уже готовы. До добавления данных остаются дополнительные unit/UI-тесты; они желательны, но не блокируют создание конфигурации 2026–27.

## Открытые вопросы владельцу проекта

Перед непосредственным добавлением сезона понадобятся ответы:

1. Ла Лига 2026–27 сохраняет 49 участников, три конференции Apertura и деление Primera/Segunda в Clausura?
2. Сохраняется ли `drawGap = 3` и правило ничьей «разница до 3 включительно»?
3. ЛЧ снова будет получаться из двух внешних турниров/API или из одного?
4. Календарь и кубковая сетка будут предоставлены готовыми либо их нужно генерировать?
5. Призы 2025–26 переносятся полностью, частично или создаются заново?
6. Нужно ли сохранять ЧМ-2026 как активное соревнование или переносить в архив вместе с 2025–26?
